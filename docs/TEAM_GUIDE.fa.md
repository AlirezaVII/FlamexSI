# راهنمای تیم Falmex

این سند توضیح می‌ده زیرساخت پروژه چطور ساخته شده و بعد از ۶ آبان که داده‌ی واقعی ناسا منتشر شد، هر کس باید کجای پروژه رو تغییر بده.

## قانون اصلی

**AI پیشنهاد می‌ده و روش آماری بررسی می‌کنه.**

- موتور تحلیل رابطه‌ها رو فقط روی ۷۰٪ آزمایش‌ها پیدا می‌کنه.
- اون رابطه‌ها بعد روی ۳۰٪ آزمایشی که موتور هیچ‌وقت ندیده تست می‌شن، و با داده‌ی به‌هم‌ریخته (permutation) هم مقایسه می‌شن.
- AI (Gemini) فقط یافته‌هایی رو توضیح می‌ده که قبلاً حساب و بررسی شدن. خودش هیچ یافته‌ای نمی‌سازه.
- هر یافته دقیقاً می‌گه از کدوم آزمایش‌ها و کدوم فایل ناسا اومده.

## یافته در برابر بینش

- **یافته (Finding):** رابطه‌ی آماری‌ای که موتور در داده دیده. همراهش این‌ها می‌آید: اعتبارسنجی روی داده‌ی دیده‌نشده، بازه‌ی عدم قطعیت، شواهد، محدودیت‌ها و بررسی متغیر سوم. یافته علت و معلول نیست.
- **بینش (Insight):** فقط وقتی ساخته می‌شود که یک پژوهشگر یک یافته‌ی معتبرشده از داده‌ی **واقعی** را بررسی و تفسیر علمی کند. از داده‌ی ساختگی هرگز بینش ساخته نمی‌شود.

مسیر کامل: داده ← تحلیل آماری ← یافته ← اعتبارسنجی ← شواهد ← توضیح هوش مصنوعی ← تحلیل عمیق ← بررسی دانش قبلی ← بررسی متخصص ← بینش ← نوآوری

## بررسی دانش قبلی (مرحله‌ی ۸)

فقط برای یافته‌های مهم، نه همه‌ی یافته‌ها. توی صفحه‌ی هر یافته بخش «Prior knowledge» هست:
- سیستم عبارت‌های جستجو می‌سازد و اول لینک منابع خود ناسا (NTRS و داده‌های PSI) و بعد Google Scholar را می‌دهد. هوش مصنوعی فقط کلمه‌ی جستجو می‌نویسد و **هیچ‌وقت منبع نمی‌سازد**.
- تیم منابع را می‌خواند و ثبت می‌کند: شناخته‌شده، تا حدی شناخته‌شده، رابطه‌ی شناخته‌شده در شرایط جدید، یا احتمالاً جدید. همراه با منبع‌ها و نام بررسی‌کننده.
- برای داده‌ی ساختگی ثبت نمی‌شود.

## بینش ایمنی آتش (مرحله‌ی ۹ و ۱۰)

بینش علاوه بر تفسیر علمی و ارتباط با ایمنی آتش، این‌ها را هم ثبت می‌کند: محدودیت‌های تفسیر، حوزه‌های کاربرد (فهم رفتار آتش، ارزیابی خطر، طراحی آزمایش، تصمیم‌گیری ایمنی، مدیریت شرایط احتراق) و یافته‌های دیگری که بینش به آن‌ها تکیه دارد.

## نوآوری (بخش دوم: فراتر از چالش)

صفحه‌ی «Innovate». هر نوآوری باید از دست‌کم یک بینش بیاید. نوعش از قبل تعیین نشده: شاخص، روش تشخیص، نقشه‌ی خطر، سیستم هشدار، ابزار تصمیم، روش پیش‌بینی یا چیز دیگر. هوش مصنوعی جهت‌ها را پیشنهاد می‌دهد (ذخیره نمی‌شود)، تیم تصمیم می‌گیرد و ایده را روی برد از «ایده» تا «دمو» جلو می‌برد و دلیل تصمیم را می‌نویسد.

## موتور سؤال‌سازی

هیچ سؤالی از قبل ثابت نشده.
- `backend/falmex/questions.py` هدف‌های کشف را از ستون‌های واقعی هر دیتاست می‌سازد.
- `backend/falmex/deep.py` برای هر یافته سؤال‌های تحلیل عمیق پیشنهاد می‌دهد: آیا متغیر دیگری توضیحش می‌دهد؟ آیا در هر گروه تکرار می‌شود؟ آیا در کل بازه برقرار است؟ آیا در فایل‌های مستقل هم تکرار می‌شود؟
- دسته‌ی جدید تحلیل عمیق با `@register_probe` اضافه می‌شود.

## داده‌ی ساختگی

دکمه‌ی «Generate synthetic» توی صفحه‌ی Data داده‌ی **ساختگی** می‌سازه («داده‌ی آزمایشی مصنوعی، نه داده‌ی آزمایشگاهی ناسا»). توی این داده این‌ها هست:
- چند رابطه که عمداً گذاشته شده.
- دو متغیر که فقط نویز هستند (`temperature` و `lab_humidity`).
- یک متغیر جعلی (`sample_mass`) که فقط همراه اکسیژن تغییر می‌کند.

تست‌ها چک می‌کنند که موتور رابطه‌های واقعی را تأیید کند، در نویز خالص هیچ چیزی تأیید نکند، و بررسی متغیر سوم نشان دهد رابطه‌ی `sample_mass` در واقع از اکسیژن می‌آید.

**از این داده هیچ نتیجه‌ی علمی نگیرید.** توی کل سیستم برچسب SYNTHETIC داره.

## تحلیل غیرخطی (اندرکنش و انحنا)

- **اندرکنش دوطرفه** (`analysis/interaction.py`): آیا رابطه‌ی یک شرط با نتیجه به مقدار شرط دیگری بستگی دارد؟ (مثلاً اکسیژن × سرعت جریان روی زمان سوختن). مدل خطی با هر دو اثر اصلی و حاصل‌ضربشان؛ اعتبارسنجی با جایگشت Freedman–Lane که اثرهای اصلی را نگه می‌دارد.
- **انحنا** (`analysis/curvature.py`): رابطه‌ای که خط راست نیست (مثلاً اول بالا می‌رود و بعد پایین می‌آید) و همبستگی رتبه‌ای آن را نمی‌بیند.
- نمودار هر یافته حالا نقطه‌های ۷۰٪ کشف (آبی) را از ۳۰٪ دیده‌نشده (نارنجی) جدا نشان می‌دهد، می‌شود با متغیر سوم رنگش کرد، و یک خط روند LOESS دارد که **فقط روی داده‌ی کشف** برازش شده است.

## تحلیل فیلم شعله (صفحه‌ی Footage)

فیلم یا عکس شعله را فریم‌به‌فریم به عدد تبدیل می‌کند: گردی Ψ (روی تصویر دوبعدی؛ نشانه‌ای از کروی‌بودن، نه اثبات آن)، شعاع معادل و نرخ رشد dR/dt، شعاع در لحظه‌ی خاموشی، و سهم پیکسل‌های آبی در برابر زرد-نارنجی (دوده‌مانند). سنجش رنگ از دوربین کالیبره‌نشده است و رادیومتری نیست. بدون کالیبراسیون (میلی‌متر بر پیکسل) طول‌ها به پیکسل‌اند و در دیتاست نوشته نمی‌شوند. نتیجه را می‌شود به‌عنوان ستون‌های `flame_*` به یک آزمایش اضافه کرد. فیلم ساختگی و داده‌ی واقعی هرگز قاطی نمی‌شوند.

## شبیه‌ساز اشتعال‌پذیری (صفحه‌ی Simulate)

نقشه‌ی احتمال سوختن بر حسب اکسیژن و گرانش (یا جریان)، برای سناریوهای ISS، زیستگاه ماه و مریخ. **فقط از داده‌ی بارگذاری‌شده** برآورد می‌شود و هیچ عدد از پیش نوشته‌شده‌ای ندارد. مرز ۵۰٪ با بازه‌ی اطمینان bootstrap نشان داده می‌شود و اگر سؤال بیرون از محدوده‌ی داده باشد، برچسب «برون‌یابی» می‌خورد. حدهای منتشرشده (مثل MOC از گزارش ناسا) را تیم با منبع کامل وارد می‌کند؛ کنار برآورد کشیده می‌شوند و هرگز با آن قاطی نمی‌شوند.

## بعد از ۶ آبان: هر نقش کجا کار می‌کنه

| نقش | فایل یا پوشه | کار |
|---|---|---|
| مهندس داده | `backend/falmex/config/variables.yaml` | اسم ستون‌های ناسا، واحدها و نقش هر متغیر (condition یا outcome) رو اینجا اضافه کن. برای این کار کد لازم نیست. |
| مهندس داده | `backend/falmex/ingest/base.py` | اگه فرمت فایل جدیده (مثلاً HDF5، تصویر یا ویدیو)، یه تابع با `@register` اضافه کن. |
| AI / Data Science | `backend/falmex/analysis/` | روش تحلیل جدید رو با `@register_analyzer` اضافه کن. به‌طور خودکار اعتبارسنجی هم می‌شه. |
| AI / Data Science | `backend/falmex/validation.py` | روش اعتبارسنجی جدید رو با `@register_validator` اضافه کن. |
| AI | `backend/falmex/ai/interpreter.py` | پرامپت‌ها اینجان. هوش مصنوعی فقط توضیح می‌ده؛ تحلیل نمی‌کنه، علت نمی‌گه و سازوکار فیزیکی توضیح نمی‌ده. |
| AI / Data Science | `backend/falmex/deep.py` و `backend/falmex/questions.py` | موتور سؤال‌سازی و تحلیل عمیق. |
| همه | `backend/falmex/findings.py` | وزن‌های رتبه‌بندی (`DEFAULT_WEIGHTS`). فعلاً همه خنثی هستند و بعد از دیدن داده‌ی واقعی تصمیم گرفته می‌شوند. |
| برنامه‌نویس / UI | `frontend/src/app/` | صفحه‌ها (Explore، Compare، Discover، Insights، Innovate، Data و جزئیات یافته). |
| همه | `backend/falmex/innovation.py` | نوع‌ها و مراحل نوآوری. |
| UX | `frontend/src/app/findings/[id]/page.tsx` | مسیر سؤال ← داده ← تحلیل ← نتیجه ← شواهد. |

## اجرا

توی `README.md` بخش «Run it» رو ببینید. کلید Gemini توی `.env` قرار می‌گیره و هیچ‌وقت نباید commit بشه.

## تست

قبل از هر push، تست‌ها رو اجرا کنید:

```bash
cd backend && .venv/bin/pytest
cd frontend && npm run lint && npm run build
```

GitHub Actions هم روی هر push همین تست‌ها رو اجرا می‌کنه.
